tonight.ink（今晚有局）UX 审计报告

日期：2026-09-10 审计方式：Chrome 真实点击体验，桌面 1343px + 手机 400px 视口，覆盖首页 / 活动列表 / 活动详情 / 发布 / 登录 / 注册 / 帮助 六类页面 站点技术栈（从页面探测）：Next.js（Turbopack）+ Supabase 存储，字体为系统 Arial/Helvetica 回退，无 PWA manifest，无 og:image

一、结论先行

当前版本是一个"合规文案包裹的活动列表"，而不是一个让留学生"今晚想出门"的产品。三个最致命的问题：

  1. 手机端主按钮（申请/报名）在详情页第 3.3 屏才出现（页面高 2856px，按钮在 2253px），且顶部固定区吃掉 23% 屏幕。
  2. 注册第一步就要"三选一"选会员套餐（Player £6.99/月、Host £6.99/月、组合 £9.99/月），在只有 3 个活动、1 个报名者的 demo 阶段，这是把用户拦在门外。
  3. 全站文案是律师口吻（"已公开信息""符合条件时可免费申请""不接收或处理付款""不会授予额外权限"），每张卡片重复两次，把夜生活/社交产品的氛围杀光了。

UI"一般般"的根因不是配色，而是：没有自定义字体、卡片信息层级混乱、没有品牌性的视觉符号、暗色主题做得像后台系统而不是像 DICE 那样的夜生活产品。

二、逐条问题清单（全部实测验证）

A. 手机端（Kai 说用户主要在手机，所以这组优先级最高）

#问题实测数据对标做法
A1顶部固定区太高：logo 行 + 覆盖范围条 + 三个 tab 三层堆叠158px / 678px 视口 = 23%Luma、DICE 手机端只保留一行 44 到 56px 的顶栏，tab 放底部或干脆去掉
A2详情页主 CTA 太深在 3.3 屏处Luma / Eventbrite / DICE 全部用底部固定 CTA 条（价格 + 报名按钮），任何滚动位置都能点
A3"首页"和"活动"两个 tab 内容几乎一样（都是那 3 个活动）两页各自 3 张卡合并成一个"发现"页，nav 减到 2 项
A4滚动时出现米白色空白闪屏（body 背景是 rgb(247,244,239) 米白，页面却是深色，重渲染时露底）手机截图捕获到整屏米白body 背景改成主题深色，或 html/body 同色
A5详情页 header 不固定，首页 header 固定，行为不一致详情页滚动后顶栏消失统一：要么都固定一行小顶栏，要么都不固定
A6发布页对未登录用户完整展示 13 个输入框、5.4 屏长表单，但顶部又说"当前不可发布"13 inputs / 3671px未登录只显示一个"登录后发布"卡片；已登录用分步表单（Luma 是 1 屏：封面 + 标题 + 时间 + 地点，其余折叠）
A7没有 PWA manifest，无法"添加到主屏幕"成 app 图标manifest = undefined留学生用手机，加 manifest + 图标 30 分钟的事

B. 转化漏斗

#问题说明建议
B1注册即选会员邮箱都没填就让选 £6.99/月 套餐，"创建账号只保存选择"这句话用户看不懂注册 = 一键（Google / Apple / 手机号），会员话题在有 30 个以上活跃活动之前不要出现在任何用户路径里
B2只有邮箱 + 密码登录留学生场景：微信是主战场，Google / Apple 是最低要求先接 Google + Apple（Supabase Auth 原生支持），微信 OAuth 需要企业主体，后置
B3卡片上没有主动作卡片唯一可见按钮是"分享活动信息"，最不重要的动作占了最显眼的位置卡片主按钮 = "我要去 / 报名"，分享改成右上角小图标
B4参与者头像模糊付费解锁"模糊参与者，Player 会员可查看清晰头像"和"女生友好"定位自相矛盾，看起来像交友软件的付费套路参与者头像免费展示（Luma 的"12 going"头像堆叠是最强社交证明），隐私由用户自己选是否公开
B53 个活动里 2 个是"内测预告 · 日期待确认"占位用户点进去没有任何可执行动作占位活动不要当正式活动展示，做成"即将上线"横条或直接不显示
B6空状态 4 个按钮"看全部活动 / 查看按日期活动信息 / 复制需求说明 / 活动提交状态"，用户搜不到活动时不需要 4 个选择一个按钮"看全部"，加一句"告诉我们你想要什么局"（收集需求）足够

C. 文案与品牌声音

#问题原文建议改法
C1免责声明堆叠每张卡"入口：符合条件时可免费申请" + "网站入口 符合条件时可免费申请"重复两遍卡片上一个字都不要，详情页底部小字一句"免费报名，Host 确认后生效"
C2内部术语外露"已公开信息""手动审核""筛选局""内测预告""临时安全信息""临时支持信息""页面展示信息 3 条"用户看得懂的：免费 / 需确认 / 女生友好 / 18+ / 10 人小局
C3城市切换、语言切换、登录按钮下都挂着一段解释"登录或退出只改变当前浏览器会话，不会提交活动申请或授予额外权限"删除。没有一个成熟产品在登录按钮下写这种话
C4SEO description 是法律文本"提供未来已公开活动信息浏览；公开不代表信息已经核验……"改成"伦敦留学生的今晚去哪：饭局、KTV、蹦迪、桌游，一个人也能来"
C5Hero 标语"今晚不想一个人"是全站最好的一句话保留让它成为品牌线，出现在分享卡片、og:image、注册页

D. 视觉 / UI

#问题说明
D1无自定义字体，Arial 回退Windows 上中文掉到微软雅黑，iOS 掉到苹方，整站没有"设计过"的感觉。加一套中文字体（Noto Sans SC 或 思源黑体）+ 一款标题展示字体即可质变
D2卡片信息密度过高一张卡有：状态 badge、5 个标签、日期、标题、两行简介、入口框、地点、主办方、网站入口行、分享按钮，共 10 层。Luma 卡片只有 4 层：封面、时间、标题、地点 + 头像
D3首页三个统计卡"页面展示信息 3 条 / 3 类 / 3 个"占了首屏，对用户零信息量，删除
D4原生 select 城市下拉白底，展开后只看见"伦敦区"一项，其余城市白字白底看不见换成自定义下拉或 bottom sheet
D5搜索框有两个清空叉（浏览器原生 type=search 的叉 + 自定义的叉）去掉一个
D6覆盖范围面板展开后盖住下方的搜索和筛选改成点击弹 bottom sheet
D7语言按钮"中文/EN"不显示当前状态改成显示目标语言："EN" 或 "中文"
D8暗色主题做成了后台风灰卡片 + 灰边框 + 白字。DICE 的暗色做法：纯黑底 + 大海报图 + 一个高饱和荧光色 + 粗标题字

E. 技术 / 稳定性

#问题实测
E1活动页 RSC 预取和参与者接口间歇 503一次会话内 3 个活动页预取 503，participants 接口 5 次调用 1 次 503。可能是 Supabase 免费层或 serverless 冷启动，上线前要查
E2参与者接口轮询，页面显示"刷新中"3 个活动的 demo 不需要轮询，改成进页面取一次
E3分享用 navigator.share 传纯文本，没有 og:image分享到微信 / WhatsApp 没有预览图。对一个靠分享传播的产品这是必须补的：动态生成 og:image（Next.js 有 ImageResponse），封面 + 标题 + 时间 + "今晚不想一个人"
E4首页大图直接加载 Supabase 原图 1600×1000，没走 next/image手机流量 + LCP 都吃亏

F. 功能缺失（对标 Eventbrite / Luma / DICE 后的差距）

  • 日期筛选（今晚 / 明天 / 本周末 / 本周）：这是"今晚有局"的名字承诺，却没有按日期看的方式
  • "谁在去"社交证明（头像堆叠 + 人数）
  • 收藏 / 想去
  • 加到日历（.ics）
  • 地图 / 距离（离 UCL / KCL / LSE 多远）
  • 价格显示（免费 / £ 多少 / AA）
  • 举办者主页（Host 过往办过几场、评价）
  • 报名后的流程页（等待确认 / 已确认 / 群入口），帮助页提到"我的"但导航里没有

三、战略层面的直话（合伙人视角）

  1. 定位和产品不一致。你说的是"聚合本地活动给留学生，像 Eventbrite"，但站上是 1 个真实饭局 + 2 个占位。聚合器的价值在供给密度，没有 30 个以上活动，用户第二次不会再打开。冷启动必须靠你们自己手动搬运：Eventbrite / Meetup / DICE 的伦敦华人相关活动、各校 CSSA 和学联活动、小红书上的伦敦局，每周至少 20 条，标注来源。这比做任何 UI 都重要。
  1. 真正的差异化不是"聚合"，是"小局"。Eventbrite 不会帮一个刚到伦敦、一个人的留学生找到 8 个人的中文 KTV 局。Timeleft（每周三 6 个陌生人吃饭）证明了"陌生人小饭局"这个模式在欧洲跑得通。建议把产品叙事从"活动列表"改成"今晚有局：帮你找到 6 到 10 个人的小局"，"创始团队饭局"这种官方主办的局就是最好的种子供给，每周自己办 3 到 5 场。
  1. 变现顺序反了。现在是先收 £6.99/月 会员再谈供给。正确顺序：用户免费、Host 免费、先把 GMV 和活跃度做出来，再向场地 / KTV / 餐厅收推广位，或者对付费活动抽成。会员付费头像解锁这个模式会让女生用户警惕，和"女生友好"定位冲突。
  1. 渠道决定设计。留学生的信息来源是微信群和小红书。所以：分享卡片（og:image 和可保存的海报图）比首页更重要；小红书风格的双列图片流比 Eventbrite 风格的列表更符合用户习惯；后续微信小程序才是终局，现在用 PWA 顶着。
  1. 品牌名。"今晚有局"是好名字，四个字有画面。"Tonight" 英文太泛，"tonight.ink" 的 .ink 后缀说不通。建议英文用 "Tonight London" 或直接拼音品牌，域名如果能拿到 jinwanyouju.com 之类的后置考虑。

四、建议的动手顺序（按 ROI）

第一周（不动架构，纯改）

  1. 删所有免责文案，改品牌口吻
  2. 加中文字体 + 标题字体
  3. 手机顶栏压成一行，去掉"活动"tab
  4. 详情页底部固定 CTA
  5. body 背景改深色，修 select 白底、双叉、覆盖范围遮挡
  6. 注册去掉会员三选一，接 Google / Apple 登录
  7. 加 og:image 动态生成 + PWA manifest

第二周（产品结构）

  1. 卡片重做（封面 + 时间 + 标题 + 地点 + 头像堆叠 + 主按钮）
  2. 日期筛选：今晚 / 明天 / 周末
  3. "谁在去"免费展示
  4. 占位活动改"即将上线"

第三到四周（供给）

  1. 手动搬运 20 条以上真实活动，每周更新
  2. 每周官方自办 3 场小局
  3. 报名后的状态页 + 微信群入口

五、参考产品（Kai 说 UI 和前端不熟，这几个可以直接去抄结构）

  • Luma（lu.ma）：活动页信息层级的教科书，大封面 + 时间地点 + Host 头像 + "X going" + 底部 Register。每个活动可以自定义主题色
  • Partiful（partiful.com）：小局 RSVP 的最佳范本，玩味字体、大 emoji、"谁在去"用表情回应，手机号一键 RSVP
  • DICE（dice.fm）：夜生活暗色主题的正确打开方式，纯黑 + 大海报 + 一个荧光色 + "Tonight" 专属入口
  • Eventbrite：日期筛选（Today / This weekend）、分类浏览、地图
  • Timeleft（timeleft.com）：陌生人晚餐配对，"一个人也能来"这个心智的先行者
  • 小红书：双列图片瀑布流，留学生已经养成的浏览习惯

设计稿见同目录的 Claude Design 画布链接（4 个方向，每个方向含手机首页 + 详情页）。
